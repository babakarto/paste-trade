# State of On-Device / Local AI on Smartphones (as of October 2026) and Developer Gaps

Research date: 2026-10-11. All dates below are the publication dates of the cited sources. Where sources conflict, both are listed.

## Key Question 1: Apple — Foundation Models framework (iOS 26 → iOS 27), model, limits, availability, developer feedback

### Takeaway
Apple ships a ~3B-parameter, 2-bit-quantized on-device model to third-party apps for free via the Foundation Models framework (iOS 26, June 2025), with a tiny context window (4,096 tokens in iOS 26; Apple's WWDC26 sample code prints 8192 for the iOS 27 model), no documented rate limits, aggressive guardrails, and foreground-only GPU access on iPhone. WWDC26 (June 8, 2026) added vision input, a `LanguageModel` protocol that lets Claude/Gemini Swift packages drop in behind the same session API, Private Cloud Compute (PCC, 32K context) access gated to Small-Business-Program developers under 2M lifetime first-time downloads, local-RAG system tools, and an open-sourcing commitment. Independent audits and developer write-ups show the on-device model confabulates heavily and over-refuses, so "Apple Intelligence for free" is real but narrow.

### Cited Findings

**Model and architecture**
- Apple's on-device foundation model is "about 3B parameters, optimized for Apple silicon," uses KV-cache sharing and 2-bit quantization-aware training (QAT); the server model is a Parallel-Track MoE running on Private Cloud Compute; framework supports LoRA adapters, guided generation and constrained tool calling (July 2025 tech report) — [Apple ML Research](https://machinelearning.apple.com/research/apple-foundation-models-tech-report-2025)
- WWDC26 (June 2026): the on-device model was "rebuilt from the ground up, with better logic and tool calling"; sample code `print(model.contextSize) // 8192`; `tokenCount(for:)` and `contextSize` arrived in iOS 26.4; guardrail false positives reduced in iOS 26.4 with "more improvements coming in iOS 27" — [Apple WWDC26 Session 241](https://developer.apple.com/videos/play/wwdc2026/241/)
- Conflicting context-window figures: multiple 2025–2026 developer posts state the on-device window is 4,096 tokens shared across instructions, history, tool output and response — [zats.io](https://zats.io/blog/making-the-most-of-apple-foundation-models-context-window/); [Natasha the Robot, June 28, 2025](https://www.natashatherobot.com/p/apple-foundation-models); [drobinin.com, June 16, 2026](https://drobinin.com/consulting/foundation-models-apple-intelligence/putting-apple-foundation-models-in-a-real-app/) — while Apple's WWDC26 code sample shows 8192 — [Apple WWDC26 Session 241](https://developer.apple.com/videos/play/wwdc2026/241/). One iOS 27 guide claims the context is "unchanged at 4096" — [ChatForest](https://chatforest.com/builders-log/apple-foundation-models-ios-27-on-device-llm-api-builder-guide/). Treat the exact iOS 27 on-device figure as unconfirmed; PCC is 32,000 tokens per Apple.
- A tool-catalog case: "the full catalog has the schemas, which overflows the 4096-token context; a compact catalog fits but has no schemas, leading to wrong arguments" — [earendil-works/pi issue #1290](https://github.com/earendil-works/pi/issues/1290)

**WWDC26 (June 8, 2026) additions**
- Vision: `Attachment(UIImage(...))` in prompts; accepts UIImage/NSImage/CGImage/CoreImage/CVPixelBuffer/file URLs; larger images cost more tokens and latency — [Apple WWDC26 Session 241](https://developer.apple.com/videos/play/wwdc2026/241/)
- `LanguageModel` protocol: `SystemLanguageModel` and `PrivateCloudComputeLanguageModel` conform; "Anthropic and Google are publishing Swift packages for their frontier models" usable via SwiftPM behind the same `LanguageModelSession`; `response.usage` exposes input/cached/output/reasoning token counts — [Apple WWDC26 Session 241](https://developer.apple.com/videos/play/wwdc2026/241/)
- PCC model: 32,000-token context; per-request `reasoningLevel` (.light/.deep); "no account setup, authentication, or API key storage"; requires an entitlement; "no cloud API costs for developers with fewer than 2 million first-time downloads"; watchOS 27 gets Foundation Models through PCC — [Apple WWDC26 Session 241](https://developer.apple.com/videos/play/wwdc2026/241/)
- System tools: `BarcodeReaderTool`, `OCRTool`, and a Spotlight search tool "enabling fully local RAG using a Spotlight index"; Dynamic Profiles (declarative per-state instructions/tools/model switching with preserved history); an Evaluations Swift framework; `fm` CLI on macOS 27; a Python SDK (`apple_fm_sdk`); the core framework, CoreAILanguageModel and MLXLanguageModel are going open source — [Apple WWDC26 Session 241](https://developer.apple.com/videos/play/wwdc2026/241/)

**PCC restrictions for third parties (June 2026)**
- Eligibility: must be in the App Store Small Business Program, have "fewer than 2 million first-time app downloads from any of their apps" (lifetime, all apps), and hold the PCC entitlement; no paid tier exists for larger developers; iCloud+ subscribers get no extra quota in third-party apps; crossing 2M or leaving the program gives a 6-month migration window; Gruber cites Gui Rambo's ChibiStudio (2M+ downloads over 10 years, little revenue) as excluded — [Daring Fireball, June 13, 2026](https://daringfireball.net/linked/2026/06/13/pcc-severely-limited-third-party-developers); also [Apple Treats](https://appletreats.substack.com/p/private-cloud-compute-models-have)
- Note the nuance: Apple's session says "iCloud+ subscribers get a higher limit" for PCC, while Daring Fireball reports no extra quota applies in third-party apps — [Apple WWDC26 Session 241](https://developer.apple.com/videos/play/wwdc2026/241/) vs [Daring Fireball](https://daringfireball.net/linked/2026/06/13/pcc-severely-limited-third-party-developers)
- Apple partnered with Google Cloud and Nvidia (June 2026) to expand PCC capacity, reportedly for Apple's own most compute-intensive Apple Intelligence requests only — [CIO Dive](https://www.ciodive.com/news/apple-teams-up-google-nvidia-expand-private-cloud-capabilities/822431/)

**Availability (devices, languages, regions)**
- Apple Intelligence (iOS 27 era, page dated Sept 15, 2026): iPhone 16 or later, iPhone 15 Pro/Pro Max, iPhone Air; iPad mini (A17 Pro), M1+ iPads/Macs, Vision Pro, Watch Series 9+/Ultra 2+/SE 3 paired to an eligible iPhone. 16 languages on iPhone/iPad/Mac: English, Danish, Dutch, French, German, Italian, Norwegian, Portuguese, Spanish, Swedish, Turkish, Vietnamese, Chinese (simplified & traditional), Japanese, Korean. Not available on devices bought in mainland China; "new Apple Intelligence features will not be available in China while Apple works through regulatory requirements"; EU users get the iOS 27 features on supported devices — [Apple Support 121115](https://support.apple.com/en-my/121115)
- At iOS 26 launch (June 2025) only 9 languages were supported (EN, FR, DE, IT, PT-BR, ES, JA, KO, ZH-Hans) — [Natasha the Robot](https://www.natashatherobot.com/p/apple-foundation-models)
- Siri AI (iOS 27) reportedly launched Sept 14, 2026 in English beta first, not initially in the EU on iOS/iPadOS/watchOS and not in China (secondary) — [Mac Observer](https://www.macobserver.com/tips/round-ups/apple-intelligence-managed-environment-what-apple-published/)

**Developer complaints / pain points**
- Rate limits: an Apple forum thread reports "I'm hitting a rate limit" when running several sessions in a loop and asks whether limits are documented; no official answer found — [Apple Developer Forums, Foundation Models topic](https://developer.apple.com/forums/topics/machine-learning-and-ai/machine-learning-and-ai-foundation-models?sortBy=oldest)
- Guardrails: a forum developer reports many articles "kicked back with a vague message about guardrails, especially with political news"; the guardrail cannot be disabled — [Apple Developer Forums](https://developer.apple.com/forums/topics/machine-learning-and-ai/machine-learning-and-ai-foundation-models?sortBy=oldest); [Natasha the Robot](https://www.natashatherobot.com/p/apple-foundation-models)
- Shipped-app problems (June 16, 2026): `.unavailable` has multiple reasons (ineligible device, Apple Intelligence off, model downloading) each needing its own fallback; the concrete reason type "has changed across iOS 26 dot releases"; `unsupportedLanguageOrLocale` and `guardrailViolation` are non-recoverable; on-demand model load adds a 1–2 s cold start (mitigated by `prewarm()`); the model "can silently skip a registered tool"; hallucinated numbers in tool-result quoting; prompt injection via tool output needs `.onToolCall`/`.historyTransform` hooks; Xcode 27 ships a Foundation Models Instrument (TTFT, tok/s) — [drobinin.com](https://drobinin.com/consulting/foundation-models-apple-intelligence/putting-apple-foundation-models-in-a-real-app/)
- Unpinnable model: Apple may update the model without schedule, developers cannot pin a version, so updates can break prompts — [Natasha the Robot](https://www.natashatherobot.com/p/apple-foundation-models)
- Quality audit (arXiv preprint, Aug 24, 2026, UC Santa Cruz + independents): Apple's `SystemLanguageModel.default` gave substantive answers at ≥80 stated confidence on 69.1% of 110 false-premise questions (vs Gemma-3-4B 26.4%, Llama-3.2-3B 12.7%, Ministral-3B 7.3%); refused 18.4% (57/310) of benign summarization requests (comparators 0%); calibration AUROC 0.47 (below chance), ECE 70.1; k=5 self-consistency sampling cut confabulation to 2.6% at 28.2% coverage. Caveats: queried "on a commodity laptop," OS build not recorded, comparators served via hosted API — [beri.net summary](https://www.beri.net/article/apple-on-device-foundation-model-audit-confabulation-consistency-sampling)
- HN sentiment: one top comment dismissed the ~3B model as good only for "basic grammar rewrites and maybe summarization"; a reply said it handles commands/summarization/answering from supplied context but hallucinates on world knowledge — [HN item 40639506](https://news.ycombinator.com/item?id=40639506); a 2026 developer post: "Honestly I can't believe Apple put that foundation model product out the door" — [HN item 47584603](https://news.ycombinator.com/item?id=47584603)

**Background inference on iOS**
- A ManifoldKit issue cites Apple DTS as saying background GPU access is limited to iPad via the `continued-processing.gpu` entitlement; iPhone apps lose GPU in background with a 4–5x CPU-fallback slowdown; `BGContinuedProcessingTask` (iOS 26) is the intended hook for user-initiated long work — [ManifoldKit issue #1713](https://github.com/ManifoldKit/ManifoldKit/issues/1713)
- llama.cpp-based iOS apps crash in background because Metal compute contexts cannot be initialized from background execution (blog, unverified against Apple docs) — [Medium](https://medium.com/@nnrajesh3006/the-tiered-inference-strategy-solving-the-ios-llm-background-crash-7e1195453188)

**On-device speech on iOS**
- SpeechAnalyzer (iOS 26+): WER 14.0% on earnings22 subset vs WhisperKit whisper-base.en 15.2% / whisper-small.en 12.8%; 10 languages vs WhisperKit's 100; no Custom Vocabulary (SFSpeechRecognizer has it); model requires a download, not preinstalled; runs on Neural Engine + CPU, hardcoded; neither offers diarization (June 20, 2025) — [Argmax](https://www.argmaxinc.com/blog/apple-and-argmax)
- SpeechAnalyzer removes SFSpeechRecognizer's one-minute session limit but is iOS 26-only; no custom wake word/VAD/intent — [Picovoice](https://picovoice.ai/blog/ios-speech-recognition/); audio-format mismatch silently yields zero transcription — [DEV Community](https://dev.to/simple_memo/ios-26s-speechanalyzer-on-a-live-mic-the-5-things-the-docs-dont-tell-you-2ng5)

### Inferences
- Apple's platform API is the most "complete" free on-device stack (model + guided generation + tools + local RAG + cloud escalation + third-party model abstraction), but every piece carries a hidden ceiling: a 4K–8K context, undocumented rate limits, unpinnable model updates, non-disableable guardrails, and PCC that most sustainably successful indies will outgrow (lifetime 2M downloads across all apps).
- The `LanguageModel` protocol (iOS 27) is effectively Apple endorsing hybrid local+cloud routing, but Apple leaves routing policy, auth, billing and key rotation to the developer — a tooling gap.
- The audit's 18.4% over-refusal and 69% confabulation suggest a market for evaluation/guardrail-wrapping tooling (self-consistency sampling, abstention, prompt-injection filters) around Apple's model.

### Gaps
- Apple's official documentation page on rate limits returned no body text; the existence of foreground vs background rate limits is only inferable from forum threads. Exact per-app quotas remain undocumented in sources found.
- Exact iOS 27 on-device context size (4096 vs 8192) is unresolved between Apple's sample code and third-party guides.
- No official Apple tokens/sec or TTFT figures for the on-device model were found; the tech report omits throughput.
- No 2026-dated structured developer survey on Foundation Models adoption was found.

## Key Question 2: Google/Android — Gemini Nano, ML Kit GenAI APIs, AICore, Prompt API, Android 16/17, Chrome, chip vendors

### Takeaway
Google exposes Gemini Nano to third-party apps only through ML Kit GenAI APIs on AICore, foreground-only, with per-app inference and battery quotas and no published token limits; device support is a hand-maintained allowlist split into nano-v2/v3/v4 tiers, and the Android 17 "Gemini Intelligence" tier requires 12 GB RAM plus a qualified flagship SoC. Gemini Nano 4 (based on Gemma 4 E2B/E4B, "up to 4x faster, 60% less battery") is in AICore Developer Preview for new 2026 flagships. Chrome's built-in AI is still desktop-only. Qualcomm, MediaTek and Samsung all tout 2x-class NPU gains, but third-party NPU access remains vendor-specific (Qualcomm GenieX preview, Snapdragon-only) with a ~3.5 GB NPU memory-mapping ceiling reported by community developers.

### Cited Findings

**ML Kit GenAI APIs / AICore (official page, read Oct 2026)**
- APIs and status: Summarization, Proofreading, Rewriting, Image Description — Beta; Speech Recognition — Alpha (Basic mode on API 31+, Advanced GenAI mode on Pixel 10/11 only); Prompt — Beta; Prompt system instructions — Beta; Prompt prefix caching — Experimental; Prompt structured output — Alpha; Prompt thinking mode — Beta — [Google ML Kit GenAI overview](https://developers.google.com/ml-kit/genai)
- Prompt API device tiers: nano-v2 (e.g., OnePlus 13, Galaxy Z Fold7, Xiaomi 15/17, POCO F7/F8, Honor Magic 7/V5, Motorola Razr Ultra 2025); nano-v3 (Pixel 9 and 10 series, Galaxy S26/S26+/S26 Ultra, OnePlus 15/15R, OPPO Find X8/X9, vivo X200/X300, Honor Magic 8 Pro, iQOO 15, Sony Xperia 1 VIII, Sharp AQUOS R11); nano-v4 (Pixel 11 series, Galaxy Z Flip8/Fold8/Fold8 Ultra). Notably Galaxy S25 series appears for Summarization/Proofreading/Rewriting/Image Description but NOT in any Prompt API tier — [Google ML Kit GenAI overview](https://developers.google.com/ml-kit/genai)
- Constraints: "Inference is allowed only when the app is in the foreground. Foreground services are not permitted"; AICore enforces a per-app inference quota (`ErrorCode.BUSY`, exponential backoff recommended), a long-duration battery quota (`PER_APP_BATTERY_USE_QUOTA_EXCEEDED`), and `BACKGROUND_USE_BLOCKED`; token/context limits are not stated; language availability "may vary depending on the particular device's configuration and the models that have been downloaded"; `getBaseModelName()` reports the Nano version — [Google ML Kit GenAI overview](https://developers.google.com/ml-kit/genai)
- Prompt API alpha announced Oct 30, 2025: "performs best on the Pixel 10 series" (nano-v3), nano-v3 shares architecture with Gemma 3n so developers can prototype with Gemma 3n; supports image + text parts, temperature/topK/candidateCount/maxOutputTokens — [Android Developers Blog](https://developer.android.com/blog/posts/ml-kit-s-prompt-api-unlock-custom-on-device-gemini-nano-experiences); moved to beta Jan 28, 2026 (secondary) — [Capawesome](https://capawesome.io/docs/sdks/capacitor/mlkit/genai-prompt/)

### Inferences
- Android's platform path is more fragmented than Apple's: three Nano generations coexist, the allowlist is per-model and per-API (S25 gets rewriting but not Prompt), and the newest capabilities (Nano 4, Gemini Intelligence) are gated to 12 GB flagships — so a third-party developer cannot assume any Nano capability exists on a given device and must check at runtime.
- The ML Kit quotas (per-app inference, per-app battery) and foreground-only rule mean "agentic" or batch workloads (indexing, summarizing a mailbox) cannot run on Nano; developers must bring their own runtime (LiteRT-LM, llama.cpp, ExecuTorch) and own model distribution.
- NPU access is real but vendor-siloed (Qualcomm GenieX/QNN, MediaTek NeuroPilot, Google TPU via LiteRT) with no cross-vendor abstraction beyond LiteRT-LM's Android NPU backend; the 3.5 GB NPU mapping ceiling effectively caps NPU-resident models near 3–4B at 4-bit.

### Gaps
- Qualcomm's official 8 Elite Gen 5 press page (404) could not be read; TOPS figures for all three 2026 flagship SoCs rest on third-party sites.
- No official MediaTek NeuroPilot third-party-app documentation or Samsung Exynos NPU SDK status for Android third-party apps was retrieved.
- Nano token/context limits and per-app quota numbers are not published anywhere found.
- Android 17 stable release date is reported inconsistently (June–July 2026 expected per one source; "shipped" per another); not resolved here.
- No primary Canalys/Google figure on how many devices are Prompt-API-eligible was found.

## Key Question 3: Open-source local inference on mobile — runtimes, apps, models, tokens/sec, memory, battery, thermal

### Takeaway
On a 2025 flagship CPU (Snapdragon 8 Elite, llama.cpp Q4_0) 1B-class models decode at ~55–105 tok/s and 3–4B models at ~17–34 tok/s; GPU/NPU paths roughly double 1B–2B decode and multiply prefill 5–10x. Gemma 4 E2B/E4B, Gemma 3n, Qwen3 0.6B–4B, Llama 3.2 1B/3B, LFM2, SmolLM3-3B and Phi-4-mini all run on 8–12 GB phones; LFM2 leads published CPU throughput. Runtime choice is a trade-off: llama.cpp (no NPU, mature GGUF ecosystem), ExecuTorch (NPU via QNN/CoreML, pre-1.0 API churn), LiteRT-LM (Google-optimized, Android-only NPU, Swift early preview), MNN (NNAPI). Thermal throttling (−30% within minutes in a 2024 study), 8 GB RAM ceilings, multi-GB downloads and iOS background limits are the recurring costs.

Note these CPU figures are far below the LFM2 report's 55 tok/s for the same model class on the same SoC; methodology differences (threads, quant, build) are not stated.
- 2024 academic study (Snapdragon 8 Gen 3, llama.cpp): ~12.7 tok/s decode falling to ~8.9 tok/s under sustained inference due to DVFS throttling; prefill peak ~56 tok/s — [arXiv 2410.03613](https://arxiv.org/html/2410.03613v1)

- Cactus (vendor claim): LFM2.5-350M at 140 tok/s on a single core, 355 MB — [Cactus Compute](https://cactuscompute.com/blog/lfm2-5-350m)
- Tool-calling on phones (May 10, 2026, updated Aug 7, 2026; llama.cpp Q4_K_M, 1,024 ctx): Qwen3-4B ~30 tok/s and Phi-4-mini 35–40 tok/s on iPhone 14 Pro (6 GB); 12–19 tok/s on Snapdragon 7 Gen 3 (6 GB), where a single tool call takes ~12–15 s end-to-end; BFCL v4 out-of-box tiers: Qwen3-4B-Instruct-2507 high-80s, Gemma 4 E4B mid-to-high 80s, Phi-4-mini low-to-mid 80s; all clear 95% after QLoRA fine-tune on 600 examples; throughput varies 10–30% with thermal state. Figures are "illustrative ranges synthesized from public benchmarks" — [Ertas AI](https://www.ertas.ai/blog/on-device-tool-calling-2026-qwen3-gemma4-phi4)

**Runtimes**
- ExecuTorch paper (May 2026): "consistently strong on CPU (via XNNPACK), achieves high token-generation throughput on mobile GPUs (via Vulkan), and unlocks substantial prefill speedups on NPUs (via QNN)"; on iOS "matches native performance through CoreML when full-graph delegation is available" — [arXiv 2605.08195](https://arxiv.org/html/2605.08195v1)
- ExecuTorch pain points: pre-1.0 API with breaking changes between minors, Java bindings less mature than C++, `.pte` export step; llama.cpp: no NPU path on Android, JNI layer is "a reference implementation, not a polished library," chat templating/context management left to developer; MNN-LLM: smaller community, opaque supported-architecture list — [AlephZero Labs](https://www.alephzerolabs.com/blog/on-device-llm-android-native-2026)
- MLC Chat "remains the Metal-acceleration reference app but has not been updated since late 2024" (secondary) — [PromptQuorum](https://www.promptquorum.com/power-local-llm/best-local-llm-apps-iphone-2026)
- Cactus SDK: optional cloud fallback for complex/large-context tasks; bindings for React Native, Flutter, Kotlin Multiplatform (Dec 2025) — [InfoQ](https://infoq.com/news/2025/12/cactus-on-device-inference/); "Qualcomm and MediaTek NPU support still in development," fallback requires API key config (vendor page) — [Cactus Compute](https://cactuscompute.com/compare/best-on-device-ai-sdk-for-android)
- Google AI Edge Gallery includes on-device function calling and a built-in benchmark (FunctionGemma: 1,916 prefill / 142 decode tok/s on Pixel 7 Pro) — [Google Developers Blog](https://developers.googleblog.com/on-device-function-calling-in-google-ai-edge-gallery/)

### Inferences
- The decode-speed frontier on 2025–2026 flagships is ~50 tok/s for 2B-effective models and ~20–25 tok/s for 4B — usable for chat and single-shot tasks, but multi-step tool-calling at 200 output tokens per hop still costs several seconds per hop, which is why mid-range phones are impractical for agentic loops.
- Published numbers are not comparable across sources (CPU thread counts, quant, context, runtime build differ by 5x for "the same" model/SoC); there is no standard mobile LLM benchmark harness that developers trust — itself a gap (Google promises Android Bench updates).
- The practical model set for an 8 GB phone is ~2B (E2B, Qwen3-1.7B, LFM2-1.2B, Llama 3.2 1B); 4B-class models are a 12 GB-phone experience.

### Gaps

- No data was found on MNN Chat or Enchanted (Enchanted is an Ollama client, not local inference).
- No current llama.cpp `llama-bench` numbers for Snapdragon 8 Elite Gen 5 or Apple A19 Pro were found.

## Key Question 4: What developers and users complain about

### Takeaway
Complaints cluster around (1) platform gating — device allowlists, 12 GB RAM floors, foreground-only inference, undocumented quotas; (2) small-model quality — confabulation, over-refusal, silent tool skipping, context overflow at 4K; (3) infrastructure friction — multi-GB downloads, no cross-vendor NPU API, pre-1.0 runtimes, iOS background GPU loss; (4) missing adjacent tooling — on-device STT/TTS parity with Whisper, RAG/vector tooling (especially on iOS), evaluation/benchmark harnesses.

### Cited Findings
- Device gating: Nano 4 features would reach ~1–3% of Android users in 2026 — [ninetwothree.co](https://www.ninetwothree.co/blog/gemini-nano-4-device-support); Gemini Intelligence needs 12 GB RAM + Android 17 — [Jetstream](https://jetstream.blog/en/gemini-intelligence-system-requirements/); Apple limits to iPhone 15 Pro+/16+ and 16 languages, none in China — [Apple Support](https://support.apple.com/en-my/121115)
- Foreground-only: ML Kit "Inference is allowed only when the app is in the foreground. Foreground services are not permitted" — [Google ML Kit GenAI](https://developers.google.com/ml-kit/genai); iPhone background GPU unavailable (iPad-only entitlement), 4–5x CPU slowdown — [ManifoldKit issue #1713](https://github.com/ManifoldKit/ManifoldKit/issues/1713); OpenClaw request for opt-in foreground inference workers notes iPhone inference "is limited to foreground use" — [openclaw issue #166970](https://github.com/openclaw/openclaw/issues/166970)
- Undocumented limits: Apple forum rate-limit question unanswered — [Apple Developer Forums](https://developer.apple.com/forums/topics/machine-learning-and-ai/machine-learning-and-ai-foundation-models?sortBy=oldest); ML Kit quotas exist (`BUSY`, `PER_APP_BATTERY_USE_QUOTA_EXCEEDED`) but are not quantified — [Google ML Kit GenAI](https://developers.google.com/ml-kit/genai)
- Context overflow and tool schemas not fitting in 4,096 tokens — [pi issue #1290](https://github.com/earendil-works/pi/issues/1290); [drobinin.com](https://drobinin.com/consulting/foundation-models-apple-intelligence/putting-apple-foundation-models-in-a-real-app/)
- Guardrail false positives (political news) — [Apple Developer Forums](https://developer.apple.com/forums/topics/machine-learning-and-ai/machine-learning-and-ai-foundation-models?sortBy=oldest); 18.4% over-refusal on benign summarization — [beri.net](https://www.beri.net/article/apple-on-device-foundation-model-audit-confabulation-consistency-sampling)
- NPU access: Hexagon 3.5 GB mapping limit, SDK behind developer account, DSP library not fully open-sourced — [ggml-hexagon #18](https://github.com/zhouwg/ggml-hexagon/discussions/18); llama.cpp has no Android NPU path; ExecuTorch has breaking changes between minors — [AlephZero Labs](https://www.alephzerolabs.com/blog/on-device-llm-android-native-2026); Cactus's own NPU support "still in development" — [Cactus Compute](https://cactuscompute.com/compare/best-on-device-ai-sdk-for-android)
- Quality for agentic tasks: out-of-box BFCL low-to-high 80s for 4B models; ~12–15 s per tool call on mid-range Android — [Ertas AI](https://www.ertas.ai/blog/on-device-tool-calling-2026-qwen3-gemma4-phi4); Apple model "can silently skip a registered tool" — [drobinin.com](https://drobinin.com/consulting/foundation-models-apple-intelligence/putting-apple-foundation-models-in-a-real-app/)
- Speech: SpeechAnalyzer 10 languages, no custom vocabulary, iOS 26-only; WhisperKit as cross-version fallback — [Argmax](https://www.argmaxinc.com/blog/apple-and-argmax); [Picovoice](https://picovoice.ai/blog/ios-speech-recognition/); Google's GenAI speech recognition is Alpha, Advanced mode on Pixel 10/11 only — [Google ML Kit GenAI](https://developers.google.com/ml-kit/genai)
- RAG: on Android Google's AI Edge RAG SDK "made integration straightforward"; on iOS "no official SDK," pipeline hand-built on TFLite + SentencePiece — [Medium / Google Developer Experts](https://medium.com/google-developer-experts/on-device-rag-for-app-developers-embeddings-vector-search-and-beyond-47127e954c24); community stacks (ONNX Runtime Mobile + sqlite-vec; VecturaKit in Swift; ObjectBox HNSW) fill the gap — [DEV Community](https://dev.to/software_mvp-factory/building-a-local-rag-pipeline-on-mobile-vector-search-with-sqlite-on-device-embeddings-and-a-311m); [VecturaKit](https://github.com/rryam/VecturaKit); Apple's Spotlight tool (iOS 27) and Google's EmbeddingGemma 2 + Semantic Retriever (Oct 2026) are the platform responses — [Apple WWDC26 241](https://developer.apple.com/videos/play/wwdc2026/241/); [Google Developers Blog](https://developers.googleblog.com/google-ai-edge-with-embeddinggemma-2/)
- Fragmentation of Nano versions: Pixel 9 placed on nano-v3 by Google but on "Nano v2" by a third-party analysis — [Google ML Kit GenAI](https://developers.google.com/ml-kit/genai) vs [ninetwothree.co](https://www.ninetwothree.co/blog/gemini-nano-4-device-support)

### Inferences
- The strongest recurring pattern is "works in the demo, breaks in the shipped app" (drobinin's framing): availability branching, quota errors, context overflow and guardrail refusals are all runtime conditions with no test harness — an opening for a cross-platform capability-detection + fallback + evaluation library.
- TTS was not covered by any retrieved source as a complaint, but no on-device neural TTS platform API for third parties surfaced either (gap, below).

### Gaps
- No r/LocalLLaMA threads were returned by search; Reddit complaints are inferred from secondary guides. A direct Reddit crawl would be needed for quotes.

- No quantitative data on app-store rejection or user churn due to model download size.

## Key Question 5: Hybrid patterns (on-device ↔ cloud routing, PCC, splits) and missing tooling for indies

### Takeaway
Both platforms now ship a hybrid primitive — Apple's `LanguageModel` protocol with PCC and Anthropic/Google Swift packages (iOS 27), Google's Nano preview with Gemma-4 parity plus Firebase/cloud fallback guidance — but routing policy, cost control, auth, privacy mode and evaluation are left to developers. Third-party SDKs (Cactus) offer automatic fallback but are early and NPU-incomplete. No retrieved source documents a production speculative/edge-cloud split for mobile LLMs.

### Cited Findings
- Apple: `LanguageModel` protocol lets on-device, PCC or third-party server models back the same `LanguageModelSession`; Dynamic Profiles can bind a branch to `.model(privateCloudCompute).reasoningLevel(.deep)`; third-party models "usually require authentication and per-token billing" and keys must not be in the binary — [Apple WWDC26 241](https://developer.apple.com/videos/play/wwdc2026/241/)
- "The developer owns routing, auth, billing, and key rotation for cloud paths, using a token provider, Keychain, and App Attest" — [drobinin.com](https://drobinin.com/consulting/foundation-models-apple-intelligence/putting-apple-foundation-models-in-a-real-app/)
- PCC is gated (Small Business Program, <2M lifetime downloads, 6-month migration, no paid tier) — [Daring Fireball](https://daringfireball.net/linked/2026/06/13/pcc-severely-limited-third-party-developers); an academic analysis states "there is no PCC API for third parties" for custom apps (likely predates/narrower than the entitlement program) — [arXiv 2605.24239](https://arxiv.org/html/2605.24239v1)
- Google: code written against Gemma 4 in the AICore Developer Preview "should run on Nano 4 devices when they ship"; recommended practice is "build an abstraction layer to swap between on-device and cloud inference"; Nano has no live data access — [ninetwothree.co](https://www.ninetwothree.co/blog/gemini-nano-4-device-support); prototype with Gemma 3n to emulate nano-v3 — [Android Developers Blog](https://developer.android.com/blog/posts/ml-kit-s-prompt-api-unlock-custom-on-device-gemini-nano-experiences)
- Cactus: routes to cloud "when a low-end Android device can't run a model at acceptable quality"; strict privacy mode can disable fallback per request type (single unverified source) — [Cactus Compute](https://cactuscompute.com/compare/best-on-device-ai-sdk-for-android); [BrightCoding](https://www.blog.brightcoding.dev/2026/04/02/cactus-ai-engine-the-revolutionary-mobile-inference-framework)
- Apple's Evaluations framework (iOS 27) is Apple's answer to prompt regression testing; Xcode 27 Instrument gives TTFT/tok/s — [Apple WWDC26 241](https://developer.apple.com/videos/play/wwdc2026/241/); [drobinin.com](https://drobinin.com/consulting/foundation-models-apple-intelligence/putting-apple-foundation-models-in-a-real-app/)
- Self-consistency wrapper (k=5, abstain on disagreement) cut Apple-model confabulation from 75% to 2.6% at 28% coverage — a client-side quality gate pattern — [beri.net](https://www.beri.net/article/apple-on-device-foundation-model-audit-confabulation-consistency-sampling)

### Inferences
- Missing for indies (no retrieved source offers them as a product): (a) a cross-platform capability probe that returns which of {Apple on-device, PCC, Nano v2/v3/v4, bring-your-own GGUF, cloud} is available with measured speed/memory headroom; (b) a policy-driven router (privacy class, latency budget, cost cap, battery/thermal state) with observability; (c) a secure token-broker/proxy for cloud keys (App Attest/Play Integrity) with per-user metering; (d) a mobile eval harness that replays prompts across on-device model versions since Apple and Google update models silently; (e) model download/caching manager with resumable, shared, deduplicated weights across apps.
- Speculative decoding or edge-cloud splitting for mobile exists in research but no shipping SDK was found; this is likely too deep for a small team versus routing/eval tooling.

### Gaps
- No evidence of Firebase AI Logic's current on-device→cloud fallback behavior from primary docs (page not fetched).
- RunAnywhere and other local-first SDKs returned no results; the SDK landscape beyond Cactus is under-documented.
- No cost data (cloud spend saved by on-device routing) from any shipped app was found.
